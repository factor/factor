# Greedy terminal-store repair: native x86 evidence

The repair removes 28 unnecessary terminal stores from integer pressure and improves its measured runtime CPU by 17.04%. It preserves all 161 mandatory physical-register assignments, every reload, and the allocator's stage/split/assignment counts.

| Measurement | Merged baseline | Repaired | Ratio |
|---|---:|---:|---:|
| Generated kernel bytes | 864 | 688 | 0.7963 |
| Actual x86 stack `mov` stores | 57 | 29 | 0.5088 |
| Actual x86 stack `mov` reloads | 29 | 29 | 1.0000 |
| Median runtime CPU seconds | 0.1748126685 | 0.1450260010 | 0.829608 |
| Median retired instructions | 3,946,650,959.5 | 3,409,050,902.5 | 0.863783 |

Sources are baseline `7b6cd9519a71960a4fb0385bf6ceeaf66097d618` and the exact greedy production file from `dca2e6e19a3818e7254c7fd1cf5e14b0b59e6b7f`. [The tested patch](tested-greedy.patch) is the only allocator production difference. Both native roots use the same newly built baseline VM, original seed, and baseline prepared image; candidate processes explicitly reload the changed greedy vocabulary. [VM/seed hashes](native-staging.json), [preparation metadata](tuning-baseline-prepare.status.json), and [953-file source verification](source-manifest.json) identify the merged baseline.

The [baseline](baseline-summary.json) and [candidate](candidate-summary.json) provenance records identify all 28 removed stores as use-only fragments ending at the original value's final use, with no original outgoing spill obligation. Immutable original ranges/uses are captured before allocation. [Structural comparison](assignment-equivalence.json) ignores changing vreg numbers and verifies the physical register for all 161 mandatory def/use positions. Final spill counts change 57→29, reloads stay 29, and all allocation counters match.

The raw [baseline](baseline-greedy-code.asm) and [candidate](candidate-greedy-code.asm) `objdump` output confirms actual emitted stack stores, independently of machine-IR counts. Matching `.bin` files retain the exact generated bytes. Code was captured immediately after selected compilation inside the allocator scope; taking it after a definition file returned had initially exposed default-allocator recompilation and was corrected before this accepted capture.

Runtime uses the untraced public greedy allocator, not the diagnostic wrapper. The exact [executed script](executed-runtime.factor) explicitly compiles both the kernel and its original workload under greedy, then invokes namespace-held word handles dynamically. Thirty-two scalar answers are checked dynamically, and every measured workload checks its independent sum of 46,080,000. Strict SSA, interval, final value-flow and rematerialization-observer checks are enabled during compilation. The archived executed version automatically added `alien.c-types` during untimed loading; the reusable parent harness now imports it explicitly.

There are two reversed process pairs, three measured samples per process, and one excluded warmup each: six measured samples per revision. Each sample runs 600 original workload iterations, or 19.2 million kernel calls. CPU ratios are 0.830452 and 0.828965 in the separate rounds. The measured retired reduction is 537,600,057 instructions, essentially the predicted 28 × 19,200,000 = 537,600,000 removed stores. [Exact medians and round ratios](runtime-summary.json) and all four raw runtime logs/statuses are retained.

These are focused integer-pressure results on native AMD x86-64, pinned to CPU 2. They establish the intended repair's effect on this kernel; they are not the later full 26-workload aggregate or a default-policy recommendation. The diagnostic provenance scripts and launchers actually executed are archived here; later edits to an owner's scaffolding are not substituted for them.
