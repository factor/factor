# Experimental greedy allocator, 2026-09-08

This implementation is an LLVM-inspired contender behind the shared allocator
selector. Linear scan remains the default. It contains its own arbitrary-order
priority queue and register interference sets; it never calls linear scan as a
fallback.

The design follows LLVM's large-range-first allocation, eviction and progressive
splitting, described in [LLVM's original greedy allocator article](https://blog.llvm.org/2011/09/greedy-register-allocation-in-llvm-30.html).
Factor-specific additions use static loop-depth weights and split at numbered
block boundaries where loop depth changes. The current [LLVM implementation](https://llvm.org/doxygen/RegAllocGreedy_8cpp_source.html)
has richer region cost models, allocation stages and recoloring. This contender
does not port those facilities. Its interference sets are vectors, weights are
`8^min(depth,3)` rather than profiles, and it does not implement rematerialization,
register hints, subregister interference or LLVM's full spill placement.

Strictly greater spill weight is required to evict every conflicting interval.
Splitting reduces the number of uses per fragment, or shortens a single-use
fragment. Minimal register uses cannot be evicted by one another; impossible
pressure raises an explicit error. Clobber splitting, representation-sensitive
spill slots, GC handling and edge resolution reuse Factor's existing machinery.

## ARM64 measurements

The matching rebuilt ARM64 VM and image were used. `measure.factor` warms each
allocator, then records three fresh CFG compilations of each of 13 existing
compiler and benchmark words. Both allocation verifiers were enabled. Raw
measurements are in `results.jsonl`.

| Corpus total | Linear scan | Greedy |
| --- | ---: | ---: |
| Generated bytes | 24,384 | 24,384 |
| Spill instructions | 42 | 42 |
| Reload instructions | 42 | 42 |
| Sum of spill-area bytes | 304 | 304 |
| Sum of per-word median allocation times | 34.76 ms | 38.04 ms |

These words did not require greedy evictions or pressure splitting. The 9.4%
allocation-time increase includes checking overhead and was measured on a
contended machine; it is not an application runtime result.

The executable `pressure-kernel` in `greedy-tests.factor` keeps 32 distinct float
values live before consuming pairwise products. Input `2.5` returns `5092.0` in
compiled code. `pressure.json` records one code-quality comparison:

| Float pressure kernel | Linear scan | Greedy |
| --- | ---: | ---: |
| Generated bytes | 848 | 832 |
| Spill/reload instructions | 12 / 12 | 11 / 11 |
| Spill-area bytes | 96 | 88 |

Greedy performed 11 evictions and 11 splits. This is a small synthetic quality
improvement, not evidence of a general performance win. The shared comparison
harness maintained by the integration worktree supplies broader runtime results.

## Verification

The allocator tests cover lifetime-hole sharing, actual eviction and requeue,
loop-weighted costs, actual loop-boundary splitting, clobber slots, keep-dst,
compiled loop arithmetic, a libc call with a live integer, boxed floats, 20,000
heap arrays and the pressure kernel. Both range non-overlap and preservation of
mandatory register uses are checked. The whole compiler suite is coordinated by
the integration worktree.

Integration testing exposed an ABI defect in the initial implementation:
memory-only clobber fragments could retain a physical register, and ABI slots
were assigned only as a side effect of creating register-backed fragments.
The corrected implementation reserves forced operand slots before splitting
and represents a fragment used solely at the clobber directly by its slot.
Two targeted regressions cover atomic and wide memory-only fragments.
`large-return-before.log` reproduces four failures from the original allocator
in the existing `compiler/tests/alien-large-return.factor` tests: wrong direct
results, an indirect-call memory fault, and a wrong nested callback result.
`large-return-tests.log` shows all five tests passing after the correction.

```sh
./factor -i=/absolute/path/factor.image -no-user-init reference/compiler-greedy-20260908/measure.factor
```
